# 六级层级 + 责任人标签 + 看板重设计：方案与落地（已实现，待 Leo 复核）

## 0. 要做什么

1. 位置编号由 5 段（州-区-楼栋-楼层-编号）改为 6 级：**部门 - 科室 - 区域 - 属地 - 位置 - 编号/命名**。
2. 层级是一棵可维护的树，**任意一级都能配责任人 / 责任部门**，下级没配就继承上级，在看板右上角以标签显示。
3. 看板首页围绕这棵树重新设计（左侧树 + 右侧状态区）。

**范围冲突提示**：`docs/design.md` 第 7 节把"区域树、逐级继承"划为第二期，本方案把其中"层级树 + 责任人继承"提前做。
**只继承责任人，不继承参数**（参数仍是"全局 + 单台 / 按前缀覆盖"）。确认本方案即视为同意这次范围调整，实现时同步改 design.md 第 1.1 / 7 节。

## 1. 数据模型

### 1.1 层级定义（固定，不开放自定义）

| 级 | 字段名（yaml / 代码） | 显示名 | 说明 |
| --- | --- | --- | --- |
| 1 | `dept` | 部门 | 树的第一层 |
| 2 | `section` | 科室 | |
| 3 | `area` | 区域 | |
| 4 | `site` | 属地 | |
| 5 | `spot` | 位置 | 对应设计文档的"录制点"所在处 |
| 6 | `number` | 编号 | 一台电脑；另有可选的**名称**（中文，如"3 号收银台"），只用于显示 |

- **每一级节点有两个值**：`code`（只用英文/数字，进文件路径，沿用原则 6）+ `name`（中文显示名，可空，空则显示 code）。
- 设备编号 = 各级 code 用 `-` 拼接，空级跳过（与现在一致），例如 `FIN-AP-E-HQ-F3-012`。

### 1.2 core（`everrec_core/config.py`、`protocol.py`）

- `Location` 的字段改为 `dept / section / area / site / spot / number`，新增可选 `label`（编号的中文名）。
- `code` 属性逻辑不变（空字段跳过）。
- **旧配置兼容**：`load_config` 容错读到旧键时自动映射并写警告，不报错、不停录：
  `state → dept`、`district → section`、`building → area`、`floor → spot`、`number → number`，`site` 留空。
  因为空级被跳过，**旧设备编号字符串完全不变**，所以录像目录、已有录像、前缀设置全部不受影响（不迁文件）。
- 心跳里的位置字段随之改名；服务端同时认旧键，滚动升级期间老 Agent 不会被拒。

### 1.3 server

新表 `org_node`（Alembic 迁移 `0009`）：

| 列 | 说明 |
| --- | --- |
| id, parent_id | 树结构；根的 parent_id 为空 |
| level | 1–5（编号不进树，设备本身就是叶子） |
| code | 英文数字，同一父节点下唯一 |
| name | 中文显示名，可空 |
| owner_name | 责任人，可空 |
| owner_dept | 责任部门，可空 |
| owner_note | 备注（联系方式等），可空 |
| updated_at | UTC 带时区 |

- `agent` 表新增列：`dept, section, area, site, spot, label`，由心跳上报并回填；`code` 列保留（唯一标识不变）。
- **迁移回填**：用现有 `agent.code` 与已上报的位置字段按 1.2 的映射生成 `org_node`，设备自动落到对应节点；旧 `location_option` 表的值作为节点名的初始来源，迁完后保留该表不删（下个版本再清理）。
- **责任人解析**：设备/节点的责任人 = 从自己向上第一个设置了 `owner_name` 或 `owner_dept` 的节点；返回时附 `owner_from`（来自哪一级节点，用于界面显示"继承自 ×× 科"）。
- 责任人**只用于显示**：本期不做账号权限、不按责任人推送告警（若要做，另开工作包并先问对接方）。

### 1.4 API（`/api/v1`，沿用现有登录态）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/org` | 整棵树，每个节点带：设备总数、各状态数、最差状态、解析后的责任人 |
| POST | `/org/nodes` | 新增节点（parent_id, code, name） |
| PUT | `/org/nodes/{id}` | 改 code / name / 责任人（改 code 受限，见 1.5） |
| DELETE | `/org/nodes/{id}` | 仅当其下没有设备和子节点时可删 |
| GET | `/devices` | 沿用；每项新增 `path`（各级 code 与 name）、`owner`、`owner_from`；`prefix` 参数沿用 |
| GET | `/agent/v1/config` | `location_options` 改为树形（客户端设置里逐级选择） |

### 1.5 必须守住的约束

- **改节点 code = 改设备编号 = 改录像路径**，会割裂历史录像。因此：已有设备的节点 **不允许改 code，只允许改 name 和责任人**；确需改 code 的，走"新建节点 + 把设备换位置"，历史录像仍留在旧编号下。
- 编号只用英文、数字、连字符的规则不变（原则 6）。
- 位置在客户端是**本地设置**（原则 5）：服务器下发的配置不能覆盖。

## 2. 设置页（网站）

新增"**组织与责任人**"一块（放在"位置选项"原来的位置，取代它）：

- 左边是层级树（部门 → … → 位置），可展开；右边编辑选中节点：
  - 显示名、code（有设备时只读，并说明原因）
  - 责任人、责任部门、备注
  - "继承来源"提示：本节点未填时，显示将继承自哪一级
- 操作：新增子节点、重命名、删除（受 1.4 限制，不能删有设备的）。
- 下方列出"该节点下的设备"，可看每台是否已归位。
- 全站风格：冷白底 + 语义状态色（只在点、徽标、浅底、文字上用），不引入组件库。

## 3. 桌面客户端设置

- 已连接服务器：位置由 5 个下拉**逐级联动**选择（部门 → 科室 → 区域 → 属地 → 位置），选项来自服务器的树；"编号"和"名称"手填（编号只允许英文数字）。
- 未连接服务器：保持可手填（只限英文数字），与现在"连不上也能独立录"的原则一致。
- 本机已存在的旧配置打开时自动映射并提示一次。

## 4. 看板（首页）重新设计

参考：海康 iVMS / 大华 DSS 的组织树、Datadog 的逐级下钻和最差状态向上汇总、Statuspage 的分组折叠、Backstage / PagerDuty 的责任人字段。

```
┌ EverRec  看板  设备墙  录像回放  设置                          退出 ┐
├────────────┬────────────────────────────────────────────────────────┤
│ 搜索…      │ 财务部 › 一科 › 东区                  [责任人 张三·一科▾] │ ← 右上角标签
│            │ ┌ 横幅：2 台需要处理 ────────────────── 更新 01:46:28 ┐ │
│ ▾ ● 财务部 │ └────────────────────────────────────────────────────┘ │
│   ▾ ● 一科 │ ████████████████████████████░░ ▮▮   (比例条)            │
│     ● 东区 3│                                                        │
│     ○ 西区 │ 需要处理 2                                              │
│   ○ 二科   │  FIN-AP-E-HQ-F3-012  录像文件 60 秒没有增长…  责任人 张三 │
│ ○ 人事部   │  FIN-AP-E-HQ-F3-015  已 6 小时没有消息…       责任人 张三 │
│            │ 离线本地录制 1 …                                        │
│            │ 正常录制 30    〔按"位置"分组的小方块，标题行带位置名〕   │
└────────────┴────────────────────────────────────────────────────────┘
```

要点：

- **左侧树**：每个节点前一个汇总灯（取下级最差状态），后面异常数/总数；有红灯的分支自动展开并排前；可搜索；可折叠；折叠时红灯照样冒泡。
- **面包屑 + 右上角责任人标签**：显示选中节点的责任人和责任部门；是继承来的则小字"继承自 ××"；没人负责显示"未指定责任人"，点一下直达设置页对应节点。
- **主区**沿用上一版：横幅、比例条、异常行置顶（写原因、多久没消息，**行内附责任人**）、正常设备小方块。小方块按"位置"分组，组标题显示位置名；设备优先显示"名称"，没有名称显示编号。
- **大屏模式**：默认选中根，主区改为"部门磁贴"（汇总灯 + 异常数 + 责任人），点进去逐级下钻；选中节点写进地址（`#/?node=…`），大屏刷新或重开后停在原处。
- **窄屏**：树收成抽屉，主区单列。
- 文字全用大白话；状态永远带文字，不只靠颜色。
- 轮询 10 秒不变；树的汇总由服务端算，前端不重复计算。

## 5. 落地步骤（一个工作包，分支 `wp10-org-tree`，四个提交）

1. **core + protocol + agent**：新字段、旧键映射、测试（含"旧配置映射后编号不变"）。
2. **server**：`0009` 迁移 + 回填、`/org` 系列接口、`/devices` 增加路径与责任人、`/agent/v1/config` 树形选项；SQLite 与 PostgreSQL 都要跑。
3. **web**：设置页"组织与责任人"、看板重写、`api.ts` 类型。
4. **desktop**：联动下拉、旧配置提示；改 design.md 与 AGENTS.md 相关表述；README 进度。

每步提交前：pytest、ruff、web build 全过。分支开始前先把当前 `wp8-board` 的未提交改动单独提交。

## 6. 验证

- Linux / 本机可自动验证：迁移回填后编号不变、责任人继承解析、树汇总、旧配置映射、`/devices` 新字段、看板用模拟数据截图。
- **需要 Leo 在 Windows 上验证**（PR 里给逐条 PowerShell 命令）：桌面客户端联动下拉在真实界面里的表现；旧安装目录升级后自动映射并能正常续录。在 Leo 回报前不写"已验证"。
